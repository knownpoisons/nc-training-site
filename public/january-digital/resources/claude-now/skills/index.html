How to turn every recurring JD document into a template Claude fills automatically — with a working skill to install today.

01  The idea

Templates that load themselves.

Everyone has done this: you ask Claude for a document — a review, a report, a one-pager — and what comes back is right but it isn't yours. Wrong layout, wrong structure, and you spend the next hour reformatting. Some of you have handed Claude an old deck and said “update this” — and watched it mangle the thing.

A skill solves it. A skill is a folder Claude carries with it: instructions, plus — the part that matters — your actual template files. Not a description of your deck. The deck. It loads itself whenever it's relevant: nothing to paste, nothing to remember. And the output isn't text to go and format — it's the finished file. The deck as a .pptx. The doc as a .docx. The sheet as a .xlsx.

Ties to Session 8
A skill is the five-layer client project made automatic. One skill per document type, one per brand — and “creative review for [brand]” comes out finished, with the brand's guardrails already applied. That's not a prompt any more. That's a system.
02  Start here

Install the one we built you.

The Session 7 offer one-pager, as a working skill. Ten minutes, start to finish.
  1. Make the folder.
    On your machine, create a folder called jd-offer-one-pager.
  2. Add the skill file.
    Copy the full SKILL.md below into a file named SKILL.md inside that folder. (The name and the .md matter.)
  3. Zip the folder.
    Right-click the folder → compress. You upload the zip, not the bare file.
  4. Upload it.
    Claude → Settings → Capabilities → Skills → upload. If your menu looks different, search “skills” in settings.
  5. Test it.
    New chat: “Write the offer one-pager for [your brand] — 15 concepts, two weeks.” Watch it arrive in the Session 7 format, as a finished file.

The skill file · SKILL.md — copy all of it

--- name: jd-offer-one-pager description: Produces the January Digital creative-production offer one-pager for a named client brand, in JD's exact Session 7 format. Use whenever someone asks for "the offer one-pager", "the offer doc", or a client-facing page explaining JD's creative production service for a specific brand. --- # JD Offer One-Pager ## When to use this skill Any request for the creative-production offer document for a client — e.g. "write the offer one-pager for [brand]". If the person names a brand, produce the document. If they don't, ask which brand before producing anything. ## What this document is The one-page, client-facing explanation of January Digital's creative production service. It is sent to a client at the start of the conversation. It sells the shift, the edge, and the value — never the tool. ## Hard rules — never break these - Never use the words: AI, artificial intelligence, machine learning, generative, synergy, leverage, unlock, journey, deep dive, ecosystem, robust, holistic, empower, scalable. - Never put a price, rate, or number of dollars on the page. Pricing is a conversation. The pricing line always stays as a pointer to that conversation. - Never promise creative for channels JD does not run. The scope is always "ready to run in the media we manage." - No emojis. No exclamation marks. British spelling throughout. - One page. If content grows beyond one page, cut — do not shrink the type. ## Structure — fixed, in this order 1. Brandline: [BRAND] × January Digital — Creative Production 2. Headline: "We don't just plan where your creative runs. We make it." (May be lightly adapted to the brand, but keep the two-sentence plan/make contrast.) 3. Sub-line: one sentence — same team that knows the media, now making the work; stills and motion; on brand; ready to run in the media we manage. 4. What you get: three bullets — [N]+ finished concepts in [timeframe]; stills and motion built to spec and channel; one creative direction produced across every SKU and format the campaign needs. 5. Why it's different here: the data edge. They already trust JD with their media, so JD knows what's performing — the creative is built from the client's own numbers. A creative shop makes something beautiful; JD makes something that works, because JD can see the scoreboard. 6. How the work gets made: the 10 / 80 / 10 — talented humans in (brief, taste, direction); production in the middle at speed (where the volume comes from); talented humans out (on brand, pixel perfect). Close with: "The speed comes from the middle. The quality comes from the two ends. We're here to protect the edges." 7. What you're paying for: not per asset, not per hour — the creative system and the speed to market. End with the pricing pointer: "[Pricing is a conversation — see how we scope it together.]" ## What to fill per use - [BRAND] — the client brand name, used in the brandline and adapted naturally into the copy. - [N] — number of concepts. If not given, ask. Never invent a number. - [timeframe] — delivery window. If not given, ask. - Adapt the examples and channel references to the brand's world (workwear ≠ beauty ≠ footwear), but keep the structure and rules fixed. ## Inputs to request if missing Ask for, in one short question: the brand, the concept count, the timeframe, and anything specific the account lead wants emphasised. Do not produce the document with placeholder brackets left in unless the person explicitly asks for the template version. ## Output Produce the finished document as a downloadable file in the format requested — default to a clean, single-page document (.docx) if no format is named. Title the file [BRAND]_JD_creative_production_offer.

Tap to select all. Once it's installed, pull it apart — this file is also the reference for how to write your own.

Stop

Before you build another skill — read this.

The starter skill carries the structure, the voice, and the behaviour of the document. It does not carry the visual identity — there's no template file in the folder yet, so the output comes back correctly built but wearing generic clothes. Right words, wrong letterhead.

The fix is one file. Put your real branded document in the folder next to the SKILL.md:

jd-offer-one-pager/ SKILL.md the rules template.docx your actual branded document — logo, fonts, colours, layout

Then add this line to the SKILL.md, under Hard rules:

- Always start from template.docx. Fill the content into the existing structure only. Never alter the styles, fonts, colours, logo placement, headers or footers.

Re-zip, re-upload, re-test. Now the output arrives in JD's clothes, every time — and the same move works for decks: your real .pptx with the master slides, filled, not redrawn.

The rule: a skill isn't finished until it carries a real template file. Structure without the brand is half a skill.
03  Then

Build your next one from a real template.

Don't write the skill by hand — have Claude build it from the document you already use.

Pick the document you make most often — the creative review, the weekly report, whatever eats your Tuesday. Attach the best recent example of it, and use this:

The build prompt

I want to turn a document template into a Claude skill so that whenever I ask for this document type, you produce it in exactly this format as a finished file. Here's the template: [attach your deck / doc / sheet] Build me the skill: 1. Write the SKILL.md — a clear name and description (the description decides when the skill triggers, so include the phrases people would actually say when asking for this document). 2. Define what stays FIXED: layout, structure, section order, tone, the rules that never bend. 3. Define what gets FILLED per use: the variables, and what to ask me for if I haven't provided them. 4. Include our hard rules: no "AI", no banned corporate words, British spelling, no emojis, no exclamation marks. 5. Package it as a folder I can zip and install, and tell me exactly how. 6. Then give me one test request to run, and tell me what a correct result looks like.

The description is the trigger — spend your effort there. If the skill doesn't fire, the description didn't contain the words you said.

What makes a skill hold — the four rules

Do
One skill per document type. Sharp trigger phrases in the description. Hard rules written as never/always. Test with three different brands before you trust it.
Don't
One mega-skill for everything (it stops triggering reliably). Vague descriptions (“helps with documents”). Rules as suggestions (“try to keep it short”). Shipping the first output untested.
04  The system

One per document. One per brand.

Where this goes: a skill for every recurring JD document — the creative review, the client report, the offer docs. And a skill for every brand — the five-layer stack loading itself: guidelines, data rules, the never-sign-offs. Then “creative review for [brand], here's the data” comes out finished, formatted, and guardrailed — from anyone on the team, on their first week or their fifth year.
